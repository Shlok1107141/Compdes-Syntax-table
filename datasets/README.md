# Datasets

DenseSym is evaluated on four datasets. Three are generated from code in this repository;
the fourth is real C source from open-source projects, which is downloaded rather than
stored here (the projects' licences vary).

| Dataset | Where it comes from | Size | Used for |
|---|---|---|---|
| Prototype set | 30 embedded-style identifiers written into [`engine/symtab_demo.c`](../engine/symtab_demo.c) and the seven `engine/variant_*.c` demos | 30 identifiers | Paper Tables 4 and 5, Figures 4 and 5 |
| Synthetic sweep | Generated by [`engine/symtab_workloads.h`](../engine/symtab_workloads.h): `realistic` (subsystem_field names), `random` (no shared prefixes), `scoped` (functions that redeclare common locals); deterministic for a given seed | n = 10 … 1,000; 168 rows (seed 1), 840 rows (seeds 1–5) | [`engine/results.csv`](../engine/results.csv), [`engine/results_seeds.csv`](../engine/results_seeds.csv) |
| Real C corpus | 93 `.c` files from five projects (below), fetched by [`fetch_corpus.py`](fetch_corpus.py) | 7,437 declarations raw; 126,374 preprocessed | [`engine/real_corpus.csv`](../engine/real_corpus.csv) |
| Arduino Uno runs | Measured on an ATmega328P board by [`firmware/tools/collect.py`](../firmware/tools/collect.py) | 468 runs | [`firmware/results/`](../firmware/results/) |

## Real C corpus

| Project | Version | Files | Download | Files used |
|---|---|---:|---|---|
| SQLite extensions | 3.46.1 | 55 | <https://www.sqlite.org/2024/sqlite-src-3460100.zip> | `ext/misc/*.c` (the 55 in the manifest) |
| GNU Readline | 8.2 | 17 | <https://ftp.gnu.org/gnu/readline/readline-8.2.tar.gz> | `examples/*.c` |
| XZ Utils | 5.6.3 | 5 | <https://github.com/tukaani-project/xz/releases/download/v5.6.3/xz-5.6.3.tar.gz> | `doc/examples/*.c` |
| GNU MPFR | 4.2.1 | 6 | <https://www.mpfr.org/mpfr-4.2.1/mpfr-4.2.1.tar.xz> | `examples/*.c` |
| DenseSym engine | commit `66b7246` | 10 | this repository | `engine/*.c` as they were when the corpus was measured |

[`corpus_manifest.csv`](corpus_manifest.csv) lists every file with its size and SHA-256.
The original measurement used the copies installed by MSYS2 (UCRT64 packages
`sqlite3 3.46.1-1`, `readline 8.2.013-1`, `xz 5.6.3-3`, `mpfr 4.2.1-2`) on Windows. They are
byte-identical to the upstream releases above, except that MSYS2 adds one
`#include "sqlite3.h"` line to `pcachetrace.c`; the fetch script applies the same line. The engine
files are taken from commit `66b7246` (with `symtab_stress.c` from its parent `b379e58`, because
that commit changed it after the run) and converted to CRLF line endings, as they were on disk.

### Download and verify

```bash
python3 datasets/fetch_corpus.py
# sqlite-ext: 55 files ... 93/93 files match corpus_manifest.csv -> datasets/corpus
```

About 21 MB is downloaded into `datasets/downloads/` and the 93 files (1.4 MB) are written to
`datasets/corpus/<project>/`. Both folders are git-ignored.

### Preprocessing and measurement

[`engine/real_corpus.py`](../engine/real_corpus.py) measures each file two ways:

- **raw**: the file as written, so only the program's own declarations. This depends on nothing
  but the file and the analyzer, and reproduces the published numbers exactly.
- **preprocessed**: the output of `gcc -E -P` (all `#include`s expanded), which is what a compiler's
  symbol table really holds. This depends on the system headers of the machine. The published
  numbers used MSYS2 UCRT64 with GCC 14.2.0 and `-I C:\msys64\ucrt64\include`; on Linux the
  totals differ, and files whose headers are missing are reported as failures.

```bash
make -C engine symtab_analyze
python3 engine/real_corpus.py --out /tmp/corpus.csv \
    sqlite-ext=datasets/corpus/sqlite-ext readline=datasets/corpus/readline \
    xz=datasets/corpus/xz mpfr=datasets/corpus/mpfr symtab-engine=datasets/corpus/symtab-engine
python3 datasets/check_raw.py /tmp/corpus.csv
# raw mode: 93/93 files reproduce engine/real_corpus.csv exactly
python3 engine/real_corpus.py --summary engine/real_corpus.csv   # tables of the published run
```

`bash scripts/reproduce_results.sh --corpus` runs all of the above.

## Synthetic sweep

```bash
cd engine
./run_sweep.sh                                        # results.csv (seed 1)
SEEDS="1 2 3 4 5" OUT=results_seeds.csv ./run_sweep.sh   # five seeds
```

The backend test `backend/tests/test_results_reproducible.py` rebuilds the sweep and fails if
`engine/results.csv` changes.
