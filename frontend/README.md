> **Stack**: React 19, TypeScript, Vite, Tailwind CSS v4, Lucide React

---

## 🌟 Overview

The frontend web application provides an interactive analysis workbench and visualizer for the **Memory-Constrained Compressed Symbol Table**. It shows, for any C code, how a **Patricia / Radix Trie**, **16-bit Arena Addressing** and **32-bit Bit-Packed Metadata** — alone and in every combination — compare with a textbook separate-chaining hash table. Every number on screen is measured by the C engine on real structures; the UI computes none itself.

---

## 🎯 Deliverables & Features

1. **Monospace Code Input Panel**:
   - Real-time line numbers and byte payload counter.
   - Quick preset selectors preloaded with realistic embedded C workloads (including the verified 30-symbol prototype from `engine/symtab_demo.c`).
   - Client-side size validation guarding against payloads exceeding the 64 KB security ceiling.
2. **Live Metrics Dashboard & Hero Display**:
   - Prominent **% Memory Saved** readout and density multiplier (e.g. `4.1x denser`).
   - Side-by-side memory consumption cards (Baseline Hash Table vs. Compressed Architecture vs. Net Bytes Spared).
   - **7-Configuration Ablation Comparison Bar Chart**: Compares the baseline against all single techniques (Trie, Arena, Bitpack), pairwise combinations and all three combined, marks whichever is smallest for the current input, and labels configurations larger than the baseline.
   - **Peak memory card**: the largest table needed at any point if each scope frees its symbols on exit.
3. **Parsed Symbol Table View**:
   - Real-time filtering by identifier name, data type, storage class (`global`, `local`, `static`, `param`), and lexical scope depth.
   - **Bit-Packed 32-bit Word Inspector**: shows the exact `uint32_t` the engine stores for each symbol (`[Type: 4b][Scope: 8b][Storage Class: 4b][Offset: 16b]`), decoded on hover.
   - **References column**: how many uses resolve to each declaration through the compressed table's scoped lookup.
   - Export to JSON for benchmark auditing.
4. **Interactive Radix (Patricia) Trie Visualizer (Showcase Demo)**:
   - Interactive tree rendering the actual string intern trie.
   - Nodes display 16-bit arena addresses (`arena[#]`) and shared prefix edge labels (e.g. `"sensor_"` -> `"temp"`, `"press"`).
   - Zoom/pan controls and click-to-inspect node details.
5. **Dual Mode Architecture (Offline Samples & Live Backend)**:
   - **Offline Samples**: the engine's real, precomputed results for the built-in presets (`src/data/sampleResults.json`, generated by `backend/scripts/build_sample_results.py`; a backend test fails if it goes stale). Custom code is refused in this mode, never estimated.
   - **Live Backend**: `POST /api/analyze` — proxied to the backend by Vite in development and by nginx in Docker (override with `VITE_API_URL`). The app switches to live automatically when `/health` reports the engine ready.
   - Error banners per status (400, 413, 422, 429, 503, 504, connection failure); a rejected input does not mark the engine offline.
